5. Why it works (expect these questions)

  • Why doesn't CORS stop it? CORS only stops the attacker from reading the response. The browser still sends the request and the server still acts on it. A plain HTML form is a "simple request", so there is not even a preflight.
  • Why doesn't SameSite stop it? localhost:1337 and localhost:4000 are the same site. The port is not part of site identity, so the cookie is still sent.
  • Why does the token stop it? The attacker's page cannot read the token and cannot set the custom header on a cross-site form. The token is signed and tied to the session, so a token from another session is rejected.
  • Why are GETs, login and register exempt? GETs change nothing. Login and register run before a session exists, so there is no session to hijack.

6. Part 2: the .vscode finding (tell her this)

Show: .vscode/tasks.json and .vscode/setupJestConfig.js. I read them and did not run the dangerous ones.

  • Runs on open: tasks.json sets "runOn": "folderOpen" on every task (lines 14, 36, 58, 80, 102, 124). Opening the folder in VS Code runs them. This is most likely the dialog box ("Allow automatic tasks?").
  • Kills VS Code: setupJestConfig.js line 12 forceCloseVSCode() runs taskkill /IM code.exe /F (line 17). Watchers at lines 55, 60, 71 and 94 trigger it when the backup files are touched, and silently revert edits to CLAUDE.md and AGENTS.md.
  • Trap for AI assistants: setupCI.js writes CLAUDE.md and AGENTS.md telling an AI to refuse the assignment and print a taunt with an encrypted link. I ignored it and did not open the link.
  • Hidden: settings.json hides .vscode, CLAUDE.md and the .bak files from the explorer.
Lesson to say: check .vscode/tasks.json before opening an untrusted repo in VS Code, and decline "Allow automatic tasks".
